# 局域网手机遥控：入口与界面方案

状态：设计建议，尚未实现。基于 2026-10-01 的映序界面和 [技术调研](lan-remote-research.md)。当前默认按“观影时临时开启，用完关闭”设计；如果实际需求是每次启动自动可用，启动策略需再调整。

## 设计目标

用户坐到远离 Mac 的位置前，能在播放器里快速开启遥控、用手机扫码配对，之后只看手机就能完成常用播放操作。开启状态和停止入口要明确。手机遥控是向 Mac 发送操作，与现有 AirPlay（向外输出播放）分开命名和呈现。

## Mac 端入口

- **主入口：`播放 → 手机遥控…`。** 选择后总是打开同一个非模态面板，不用菜单项直接切换开关。因为用户开启后还需要看到地址、二维码和配对码。无媒体播放时也可以打开。
- **状态：**菜单项在开启后显示 `手机遥控…（已开启）`；控制层显示时可在画面右上角放一个很轻的手机连接标记，点击也打开面板。控制层隐藏时标记一并隐藏，避免在画面上留下常驻元素。这个标记是状态与返程入口，不承担首次发现。
- **不在底部控制栏加常驻按钮。** 现有右侧已有音量、AirPlay、播放列表、全屏，窄窗口还会收起部分控件。遥控入口不是逐分钟操作，常驻按钮会让高频播放操作更拥挤。
- 面板关闭不等于停止服务；只有明确点击“停止遥控”或退出映序才停止。下次启动默认关闭，除非用户另行选择记住开启状态。

## Mac 端面板

同一个面板根据状态换内容；标题固定为“手机遥控”，避免弹出多个窗口。

**未开启**

```text
手机遥控                                      未开启

用手机浏览器控制这台 Mac 上的映序。
手机和 Mac 需要能在同一局域网中互相访问。

                         [开启手机遥控]
```

**已开启**

```text
手机遥控                                      ● 已开启

 [二维码]       扫码打开控制页
                http://192.168.x.x:端口/  [复制地址]
                当前网络：Wi-Fi / 192.168.x.x  [更换]

 配对码        123 456       2 分钟内有效  [刷新]
                在手机页面输入配对码即可连接

 已连接设备    iPhone · 最近活动：刚刚   [断开]
                [添加另一台设备]

                                      [停止遥控]
```

- 初次开启显示短期配对码；首台设备配对后收起配对码。用户点“添加另一台设备”才生成新码。二维码只包含控制页地址，不放长期密钥。
- 地址能复制、网络接口能切换；若只有一个可用地址，不必露出“更换”。切换网络后更新地址和二维码，并明确提示已有手机要重新打开新地址。
- “已连接设备”仅统计最近仍有通信的设备；断开设备立即撤销其会话。设备名称如果无法可靠取得，用浏览器/设备类别等中性名称，避免假装能识别机主。
- 加载、启动失败、本地网络权限拒绝、端口占用和网络断开都在面板内解释，并提供“重试”。不能用“已开启”表示仅仅创建了服务对象；必须成功监听后再显示该状态。

## 手机端

手机浏览器直接打开映序提供的本地页面；深色界面沿用映序的炭灰、浅色文字和淡蓝强调色，页面本身不展示视频画面。

**首次进入：**显示“连接到映序”、一个适合数字键盘输入和粘贴的六位配对码输入框、“连接”按钮，以及清楚的错误反馈。会话在本次桌面遥控服务关闭前有效；刷新页面仍可继续使用。

**已连接：**

```text
映序                                      ● 已连接

当前播放
影片或剧集文件名（最多两行）

────────────●─────────────────────────────
12:08                                 42:34

 [上一集]   [−10 秒]   [播放/暂停]   [+10 秒]   [下一集]

音量       ━━━━━━━━━●━━━━━━━━━━━━           60%

[播放列表]  打开当前目录的剧集列表
```

- 播放/暂停为最醒目的主操作；进度条可拖动，点击 `±10 秒` 有即时反馈。上一集/下一集与快退/快进用文字或不同图形明确区分。
- 播放列表作为独立的底部抽屉，显示文件名、当前项和数量；手机端不显示绝对文件路径，也不开放任意路径输入或上传。
- 触控目标至少约 44 × 44 CSS 像素；竖屏单手可用，横屏时核心按钮仍保持一行。状态每约 1 秒同步一次，点按后立即更新；暂时失联时禁用命令并显示“正在重新连接”。
- Mac 尚未打开媒体时显示“请先在 Mac 上打开视频或音频”，播放按钮和进度条禁用，保留连接状态。

## 状态与文案约束

| 状态 | Mac 端 | 手机端 |
| --- | --- | --- |
| 服务未开启 | `未开启`、开启按钮 | 旧页面提示“遥控已关闭” |
| 服务已开启、未配对 | 地址、二维码、配对码 | 输入配对码 |
| 已配对 | 已连接设备、断开、停止 | 可控制播放 |
| Mac 换网或睡眠后不可达 | 更新地址或提示重试 | 明确显示失联，不假装指令已执行 |
| 权限/防火墙阻止 | 说明需在 macOS 允许连接；保留重试 | 若页面已打开，显示连接失败 |

首版不做视频串流、电脑文件选择、AI 字幕设置或互联网访问；这些都会明显增加权限、复杂度或安全面。
